Portfolio : hébergement AWS et déploiement continu

Le site que vous lisez : des fichiers statiques dans un bucket S3 privé, distribués par CloudFront, mis en ligne automatiquement à chaque push.

Période
2026
Contexte
Projet personnel
Rôle
Seul
Stack
S3, CloudFront, ACM, Route 53, IAM, GitHub Actions

01Le problème

Mettre un site statique en ligne sur mon propre nom de domaine, en HTTPS, sans serveur à administrer, et pouvoir le mettre à jour sans manipulation manuelle. Deux contraintes : ne stocker aucune clé d'accès AWS dans le dépôt GitHub, et garder une facture de quelques centimes par mois.

02Ce que j'ai fait

  • Bucket S3 privé, jamais exposé : CloudFront le lit via un Origin Access Control. L'hébergement de site statique de S3 a été écarté, il impose un bucket public.
  • CloudFront comme seule porte d'entrée : certificat ACM pour le HTTPS, et redirection de HTTP vers HTTPS.
  • Domaine acheté chez Gandi, DNS délégué à Route 53 par ses quatre serveurs de noms.
  • Déploiement par GitHub Actions : le workflow s'authentifie auprès d'IAM par OIDC et endosse un rôle temporaire, plutôt que de stocker une clé d'accès dans le dépôt.
  • Pages d'erreur personnalisées et restriction géographique configurées sur la distribution.

03Le résultat

  • Site en ligne sur noameunier.fr en HTTPS, servi depuis le cache CloudFront.
  • Une mise à jour se résume à un push sur main : le workflow envoie le dossier site/ vers S3 puis vide le cache, et la nouvelle version est en ligne en une minute environ.
  • Environ 0,50 $ par mois : la zone Route 53 est le seul poste réellement facturé.
